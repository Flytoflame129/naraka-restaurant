# 正式菜单详情与每日推荐设计

## 目标

将现有 15 道正式菜单条目扩展为可阅读、可进入详情页的完整虚拟菜品，并用它们替换首页当前单张考据型推荐卡。首页每天稳定展示三道推荐菜，聚窟洲、火罗国、龙隐洞天各一道。

## 内容边界

- 15 道菜是无间食肆的虚拟菜单设定，不包装成已经考证的游戏事实。
- 菜名由用户确认；扩写内容只描述菜品、席面氛围和同好创作设定。
- 没有可靠来源时，不补写梗起源、官方设定、角色台词或技能效果。
- 原有 `dishes` 集合继续承载需要来源、可信度和考据状态的菜品档案。
- “振刀脆响酥”保留原详情页，但不再占用首页每日推荐区域。

## 内容模型

继续使用 `menuItems` Content Collection，不复制到 `dishes`。每个正式菜单条目包含：

- `title`: 菜名。
- `slug`: 稳定路径标识。
- `map`: 聚窟洲、火罗国或龙隐洞天。
- `category`: 主食、小吃、饮品、招牌菜、怪菜或套餐。
- `description`: 卡片短描述。
- `order`: 地图席面内排序。
- `dishIntro`: 详情页菜品介绍。
- `dishSetting`: 虚拟菜品设定。
- `playerComment`: 席间趣评，不冒充社区原话。
- `recommendedPairing`: 推荐搭配。
- `relatedElements`: 与菜名有关的角色、武器、地点或操作关键词；不确定时只使用菜名已明确表达的元素。
- `image.src`: AI 生成图片路径。
- `image.alt`: 客观替代文本。
- `image.credit`: 固定标注“AI 生成原创视觉，由项目维护者整理”。
- `image.license`: 固定标注“项目原创生成图，仅供本站非商业展示”。

`scripts/validate-content.mjs` 同步检查以上字段、图片文件存在性、AI 说明和现有 `8 / 4 / 3` 数量规则。

## 页面结构

### 菜单页

- 保留三主题筛选和 15 道菜的现有排序。
- `MenuItemCard` 增加明确的详情入口，但保留当前主题边框、底纹、分类签牌和完整视觉层级。
- 卡片显示菜名、地图、分类和短描述，不显示档案号、可信度或审核提示。
- 详情链接指向 `/menu/[slug]/`。

### 正式菜单详情页

新增 `src/pages/menu/[slug].astro`，静态生成 15 个页面。结构为：

1. 菜品 Hero 与 AI 图片。
2. 菜品介绍。
3. 菜品设定。
4. 席间趣评。
5. 推荐搭配。
6. 相关江湖元素。
7. AI 图片说明与“本站虚拟菜品二创”说明。

详情页不显示来源考据、可信度或发布审核字段，因为这些条目属于明确的食肆原创菜单设定。

### 首页每日推荐

- 删除首页当前读取 `dishes` 的单张“振刀脆响酥”推荐区域。
- 首页从 `menuItems` 读取三组候选，并预渲染三张带图推荐卡。
- 每天聚窟洲、火罗国、龙隐洞天各选一道。
- 推荐卡显示图片、地图、菜名、分类和短描述，并链接详情页。

## 每日轮换算法

客户端使用访问者本地日历日期生成稳定日序号：

```js
const now = new Date();
const dayNumber = Math.floor(Date.UTC(now.getFullYear(), now.getMonth(), now.getDate()) / 86_400_000);
```

每个主题按既有 `order` 排序，再使用不同偏移量选取：

- 聚窟洲：`dayNumber % 8`
- 火罗国：`(dayNumber + 1) % 4`
- 龙隐洞天：`(dayNumber + 2) % 3`

同一本地日期内刷新结果不变，跨日后自动轮换，不依赖后端、定时构建或 API。无 JavaScript 时显示每个主题排序第一的菜品作为回退。

## 图片设计

为 15 道菜分别生成一张 `1600 × 900` 横向东方幻想宴席概念图，并输出为 WebP：

- 聚窟洲：雾林、古木、暖灯、暗金边饰。
- 火罗国：沙海、古城、烈宴、赤红与焦橙。
- 龙隐洞天：辉煌地宫、紫色北斗星盘、冷青与古铜。

每张图必须让对应菜品成为清晰主体。禁止出现《永劫无间》官方角色、Logo、截图、宣传素材、可识别 UI 或仿制官方文案。

图片保存到 `public/assets/dishes/menu/`，文件名与 `slug` 一致。生成后制作联系表检查构图、主题归属、文字伪影、重复杂物和菜品可辨识度。

## 组件边界

- `MenuItemCard.astro`: 菜单列表卡，继续负责紧凑信息层级和主题样式。
- `DailySpecialCard.astro`: 首页三张带图推荐卡，只消费完整的 `menuItems` 数据。
- `src/pages/menu/[slug].astro`: 正式菜单详情页。
- `src/pages/index.astro`: 只组织每日推荐候选与轮换脚本，不包含菜品文案。
- `src/content.config.ts`: `menuItems` schema 的唯一字段接口。

## 响应式与可访问性

- 首页推荐在桌面三列、窄屏单列。
- 菜名与描述不得裁切；长菜名使用现有长标题规则。
- 图片提供准确 `alt`，固定 `16 / 9` 比例，避免布局跳动。
- 每张可点击卡只有一个明确链接，具备键盘焦点样式。
- `prefers-reduced-motion` 下不增加过渡动画。

## 验证

- `npm.cmd run validate:content`
- `npm.cmd run build`
- 确认生成 15 个 `/menu/[slug]/` 页面。
- 确认首页始终显示三道推荐且每个主题各一道。
- 确认无 JavaScript回退仍显示三道菜。
- 使用桌面与手机截图检查首页、菜单页和最长菜名详情页。
- 检查项目中不存在官方图片、Logo、截图或角色素材。
