# NARAKA Restaurant 视觉返工与项目 Skills 优化设计

## 目标

在不新增搜索、评论、登录、后端和复杂 API 的前提下，将现有 Astro MVP 从通用暗色内容站提升为具有《永劫无间》玩家同好气质的“虚拟游戏主题餐厅”。视觉采用原创东方幻想素材，不复制游戏官方 Logo、角色、截图、宣传图、UI 或文案。

本轮同时优化项目内 6 个 Codex skills，使页面开发、内容研究、菜品写作、schema 校验、版权审核和上线检查使用一致的项目规则。

## 设计选择

采用“电影感主视觉 + 江湖情报板”混合方案：

- 首屏和地图入口负责建立世界观与视觉冲击。
- 菜品、来源、投稿要求使用情报板、悬赏榜和委托书式信息结构。
- 保留虚拟餐厅设定，但不使用普通餐饮电商的价格、购物车或外卖卡片语言。
- 使用 Astro、原生 CSS、现有少量 JavaScript；不新增 UI 框架、动画库或运行时框架。

## 原创视觉资产

生成 4 张不含文字的原创位图：

1. 首页 Hero：夜色中的东方幻想食肆，黑金红主色，远景山雾、灯火和宴席形成视觉纵深。
2. 聚窟洲：雾林、古树、岛屿栈道与隐约食肆灯火，深墨绿、暗金、温红、雾白。
3. 火罗国：沙海、烈日余晖、古城机关与宴席，沙金、赤红、焦橙、深褐。
4. 龙隐洞天：地宫、矿洞、龙纹机关与幽光后厨，曜黑、熔岩红、冷青、古铜金。

所有资产必须满足：

- 不出现《永劫无间》角色、武器造型、Logo、商标或可识别官方 UI。
- 不模仿具体官方海报构图，不加入游戏官方文案。
- 图片只作为本站原创同好氛围素材，并在仓库文档记录生成说明。
- 输出为适合网页的宽幅位图；首屏优先加载，地图图在进入视口前延迟加载。

## 全局视觉系统

### 色彩

- 基础背景：近黑、炭黑和暖黑，不使用单一纯黑平铺。
- 品牌强调：深红、朱红、暗金。
- 聚窟洲强调：墨绿和雾白。
- 火罗国强调：沙金和焦橙。
- 龙隐洞天强调：冷青和古铜。
- 所有组件只使用语义化 CSS Variables，不在页面组件中散落色值。

### 排版

- 标题采用系统可用的中文宋体/衬线字体栈，正文采用中文无衬线系统字体栈，避免依赖外部字体服务。
- Hero 标题保持强仪式感，但通过 `clamp()`、可控行宽和移动端断行避免溢出。
- 正文字号移动端不低于 16px，段落行高保持 1.6 至 1.8。
- 不使用负字距，不让装饰字体承担长段阅读。

### 组件语言

- 面板边角保持 0 至 6px，使用切角、细金线、印章和编号强化游戏活动页感。
- 卡片悬停只改变边框、亮度和小幅位移，不改变布局尺寸。
- 状态必须同时使用文字和视觉标记，不能只靠颜色表达。
- 所有交互目标至少 44px，高对比焦点态必须可见。
- 动效控制在 150 至 300ms，并支持 `prefers-reduced-motion`。

## 页面设计

### 首页 `/`

- 使用全宽 Hero 背景图，左侧承载站点定位、主标题、副标题和两个行动按钮。
- 右侧不再使用抽象空面板；改为叠加式“今日席位”信息和非官方印章。
- 主标题“聚窟开席，劫味上桌”在桌面端保持一行，在窄屏按完整语义断行。
- 主题切换后，Hero 背景、说明和强调色同时变化。
- 三个地图入口使用原创地图横幅，展示地图名、气氛和适合内容类型。
- “今日招牌菜”“玩家热梗”“投稿入口”使用活动情报分区，不引入新业务功能。

### 菜单页 `/menu`

- 页头改为宽幅情报板，筛选器保持原生按钮和现有 JavaScript。
- 菜品卡展示编号、地图、菜名、可信度、梗类型、分类及角色/武器/操作线索。
- 卡片图像是内容视觉，文本区域采用游戏资讯卡层级，不模拟商品价格或购买操作。
- 无菜品主题显示明确空状态，同时保留地图氛围。

### 菜品详情 `/dishes/[slug]`

- 顶部使用菜品图和档案信息组成 Hero。
- 正文维持菜品介绍、梗来源、菜品设定、玩家吐槽、推荐搭配、待考证说明，不改变内容模型。
- 侧栏改为“情报档案”，来源列表明确展示来源类型、可靠性、核查日期和支撑说法。
- 本站原创命名和吐槽与来源事实保持视觉分区。

### 投稿页 `/submit`

- 使用“后厨委托书”视觉，主按钮仍跳转 GitHub Issue Form。
- 投稿条件按梗名与出处、关联线索、图片授权、展示许可组织。
- 明确投稿不等于发布，待考证、授权不明和社区风险内容会被阻塞。

### 画廊页 `/gallery`

- 保留当前空状态，不生成虚构社区作品。
- 使用陈列档案页头和清晰授权规则，未来内容仍由数据文件驱动。

### 关于页 `/about`

- 使用简洁宽幅页头和项目章程式内容。
- 非官方声明、权利归属和撤稿路径保持显著，不采用官方公告语气。

## 代码边界

- `src/data/mapThemes.ts` 继续作为三地图展示信息的单一来源。
- `src/styles/global.css` 负责设计 tokens、全局布局和现有组件样式。
- 页面只组织语义结构，菜品数据继续来自 Astro Content Collections。
- 可新增少量纯展示组件，例如地图入口或页面标题；仅在能减少真实重复时创建。
- 不改变菜品 schema、发布状态和来源审核逻辑，除非视觉组件需要读取已有字段。
- GitHub Pages 的 `sitePath()` 路径处理必须保留。

## Skills 优化范围

按单个 skill 逐一调整和验证：

1. `naraka-meme-research`：输出字段对齐当前来源证据对象，明确来源支撑说法。
2. `meme-to-dish-writer`：对齐当前 `status`、`publishStatus` 和正文结构，区分事实与本站二创。
3. `dish-schema-keeper`：以 `src/content.config.ts` 和 `scripts/validate-content.mjs` 为实现真相，减少重复枚举造成的漂移。
4. `copyright-source-review`：把非官方声明、原创 AI 图片说明、来源—结论对应和授权阻塞统一为一个审核流程。
5. `astro-site-builder`：加入 `ui-ux-pro-max` 设计系统查询、`docs/design-direction.md`、响应式和可访问性检查顺序。
6. `deploy-quality-check`：加入 375px、768px、1440px 页面检查、三主题差异、文字溢出、reduced-motion 和图片授权检查。

每个 skill 保留 `name`、`description`、`when_to_use`、`workflow`、`output_format`、`guardrails`，正文以中文为主，描述以 `Use when` 开头。优化目标是减少重复、强化完成标准，不增加脚本或依赖。

## 版权与非官方边界

- 每个页面继续通过 Footer 展示完整非官方声明。
- 首页首屏额外保留简短“非官方玩家同好创作站”提示。
- AI 视觉资产不得被描述为官方素材、游戏截图或概念原画。
- 不生成或使用可识别游戏角色、官方服装、武器、地图截图和 Logo。
- 不把待考证菜品提升为公开内容；本轮不新增菜品。

## 验证标准

- `npm run validate:content` 通过。
- `npm run build` 通过，公开详情页仍只由允许公开的菜品生成。
- 首页、菜单、菜品详情、画廊、投稿、关于页均可访问。
- 在 375px、768px、1440px 宽度检查无横向滚动、文字溢出或导航遮挡。
- 三个主题在 Hero、主题入口和强调色上具有可辨识差异。
- 主题选择刷新后保持，按钮 `aria-pressed` 正确。
- 键盘焦点清晰，主要按钮和主题按钮满足最小触控尺寸。
- reduced-motion 环境下移除非必要位移和过渡。
- 所有新增图片具有替代文本、稳定尺寸和原创生成说明。

## 明确不做

- 不新增评论、搜索、登录、支付、购物车、后端或复杂 API。
- 不新增 GSAP、Tailwind、React、Vue、图标库或大型 UI 框架。
- 不创建虚构玩家评价、虚构社区作品或无来源新梗。
- 不修改现有菜品发布结论和来源证据。
- 不复制官网布局细节、素材、Logo、角色或文案。
