# 全站基础体验与强氛围动效设计

## 背景

NARAKA Restaurant 已具备完整的 Astro 静态站点骨架、内容集合、地图主题、明暗模式、菜单与详情页面。本次工作不重做视觉方向，也不改变内容模型、页面 URL 或部署方式，而是在现有暗色武侠与金红视觉基础上加固全站基础体验。

本次以手机端和桌面端同等标准验收。动效采用“强氛围动态”方向：允许持续光效、明显位移、景深和更有冲击力的页面转场，但必须满足性能、可访问性和静态降级要求。

## 目标

- 提升导航、页面框架、响应式布局和交互反馈的一致性。
- 让桌面与移动端都拥有完整、清晰的浏览体验。
- 用强氛围动效强化游戏活动页与江湖食肆的仪式感。
- 保持 Astro 静态优先、内容优先和渐进增强架构。
- 不引入动画库、重型 UI 框架、后端或新内容系统。

## 非目标

- 不全面更换现有视觉设计。
- 不改写菜品内容、来源结论或内容 schema。
- 不新增搜索、账号、数据库、CMS 或投稿后端。
- 不修改现有公开 URL 和 GitHub Pages 部署方式。
- 不复制游戏官方素材、Logo、UI 或文案。

## 全站框架

### 顶栏与导航

桌面端继续使用横向主导航。移动端使用语义化菜单按钮展开折叠菜单，菜单包含现有全部页面入口，并将地图主题切换与明暗模式控制从主链接中分组展示。

移动菜单需要具备以下行为：

- 按钮通过 `aria-expanded` 和 `aria-controls` 表达状态。
- 打开后锁定背景滚动，并把焦点移入菜单中的第一个可操作项。
- Escape、关闭按钮、点击遮罩或完成页面跳转均可关闭菜单。
- 关闭后焦点回到菜单触发按钮。
- JavaScript 不可用时，主导航链接仍然可见且可访问。

顶栏根据滚动状态适度收紧，但不能完全隐藏导航。滚动变化只影响视觉密度，不改变布局宽度或交互位置。

### 页面结构

全站统一容器宽度、章节间距、标题换行、按钮行和响应式断点。Hero、卡片网格、详情页双栏、筛选区和页脚使用同一组布局规则，避免中间宽度下出现不一致的折行和列数变化。

关键验收宽度为 375px、768px、1024px 和 1440px。所有页面不得出现非预期横向滚动，固定顶栏不得遮挡锚点、焦点或页面首段内容。

## 动效语言

### 页面转场

页面转场使用 450–650ms 的淡入、纵深位移与轻微缩放组合，呈现电影感。转场仅使用 `opacity` 和 `transform`，不得阻塞导航，也不得导致布局重算或内容闪烁。

### Hero 与主题切换

Hero 可使用缓慢漂移的雾层、扫光、景深缩放和低频环境光。地图主题切换时，背景图片交叉淡化，标题和说明按层级错峰过渡。持续动效必须限于 Hero 或主题背景等少数氛围区域，不覆盖长篇正文。

### 内容入场与卡片反馈

章节进入视口时使用分层上浮与淡入，卡片在组内按顺序错峰出现。已进入过的内容在同一次页面访问中不重复播放长入场动画。

桌面端卡片悬停可使用抬升、光边、阴影增强和图片轻微推进。键盘焦点必须获得同等清晰但不依赖运动的反馈。触屏端不依赖悬停，使用短促按压反馈和滚动入场。

### 性能与减少动态效果

- 动画只使用 `transform`、`opacity` 和必要的合成层友好效果。
- 避免动画 `width`、`height`、定位尺寸和大面积实时模糊。
- 移动端降低持续光效、模糊和叠层数量。
- `prefers-reduced-motion: reduce` 下停用持续动画、错峰入场和明显位移，保留即时状态反馈。
- 动效控制器不可阻塞首次内容渲染。

## 组件边界

### `Navbar`

负责主导航数据、当前页状态、移动菜单结构和触发按钮。桌面与移动端共用同一份链接数据，避免两套导航内容漂移。

### 移动菜单控制器

使用一个轻量客户端脚本处理展开状态、背景滚动、Escape、遮罩关闭和焦点恢复。脚本只增强现有语义化 HTML，不负责生成导航内容。

### 动效控制器

使用一个轻量客户端控制器统一管理滚动入场、顶栏滚动状态和一次性播放标记。页面转场继续由 Astro 提供的能力承担。组件通过少量 `data-*` 属性声明动效意图，避免在每个组件中复制脚本。

### CSS 动效工具

在全局样式中建立持续环境动效、页面入场、章节入场、错峰延迟、交互反馈和减少动态效果规则。所有颜色与阴影继续使用现有语义变量，地图主题差异通过当前主题 token 表达。

## 图片与页面稳定性

保留现有 Astro 图片处理方式。内容图片需要明确宽高或宽高比，首屏关键图与非首屏图片采用不同加载优先级，非首屏图片延迟加载。图片加载前后不得改变卡片和 Hero 的主要布局尺寸。

## 渐进增强与异常降级

- JavaScript 失效时，页面内容、链接、默认地图主题和明暗主题基础样式仍可用。
- 移动导航在无脚本状态下不得永久隐藏。
- 动效控制器失败时，内容默认可见，不能停留在透明或移出视口状态。
- 页面转场后需要重新同步导航当前状态、移动菜单关闭状态、主题状态和滚动入场观察器。
- 动画不得改变 DOM 阅读顺序或键盘 Tab 顺序。

## 可访问性

- 所有可操作目标至少 44×44px，并保持可见焦点环。
- 移动菜单具备可读名称、展开状态、明确关闭路径和焦点恢复。
- 当前页面不能只依靠颜色表示，需要保留 `aria-current="page"` 和可见样式差异。
- 明暗主题分别满足正文、辅助文字、边框、按钮和焦点状态的可辨识性。
- 动画不闪烁，不制造快速重复亮度变化，不妨碍阅读或操作。
- 系统减少动态效果设置必须覆盖页面转场、持续氛围动画和滚动入场。

## 验证方案

### 自动验证

- 运行 `npm run validate:content`。
- 运行 `npm run build`。
- 检查构建过程中无 Astro、内容 schema 或客户端脚本错误。

### 手动验证

- 在 375px、768px、1024px 和 1440px 宽度检查首页、菜单、详情、画廊、投稿与关于页。
- 使用键盘完成主导航、移动菜单、主题切换和页面主要链接操作。
- 验证 Escape、遮罩关闭、焦点进入和焦点恢复。
- 验证普通动态与 `prefers-reduced-motion` 两种模式。
- 禁用 JavaScript 后确认内容和导航基础可用。
- 验证页面转场后菜单、主题、滚动状态和入场动画不重复绑定。
- 检查页面无横向滚动、图片加载无明显布局跳动、固定顶栏不遮挡焦点。

## 完成标准

- 全站现有页面和内容保持可访问，URL 与内容 schema 不变。
- 手机和桌面导航均清晰、完整、可通过键盘操作。
- 强氛围动态在支持设备上可见、流畅，并集中在 Hero、页面转场和内容入场。
- 小屏设备自动降低持续效果，减少动态效果模式提供完整静态回退。
- 无 JavaScript 时不存在隐藏内容或不可达导航。
- 内容验证与静态构建全部通过。
