# 开发路线图

本路线图把项目拆成 7 个阶段。每个阶段都应能独立验收，避免一次性搭建过大范围。

## 阶段 1：项目治理与内容边界

**目标**：建立协作规则、产品边界和领域语言。

**交付物**：

- `AGENTS.md`
- `CONTEXT.md`
- `docs/PRD.md`
- `docs/domain-model.md`
- `docs/roadmap.md`
- `docs/tech-decision.md`

**验收标准**：

- 明确项目是非官方玩家同好创作站。
- 明确“不无来源编造梗”和“待考证”规则。
- 明确第一版不安装依赖、不创建完整站点脚手架。

## 阶段 2：初始化 Astro 静态站点

**目标**：建立最小 Astro 项目，能在本地启动并构建。

**交付物**：

- Astro 项目结构。
- GitHub Pages 兼容配置。
- 基础布局、全局样式、站点元信息。
- `package.json` 中的 `dev`、`build`、`preview` 命令。

**验收标准**：

- `npm run dev` 能启动本地站点。
- `npm run build` 能生成静态产物。
- 首页显示非官方声明。

## 阶段 3：内容模型与 Markdown 数据

**目标**：把 Meme、Dish、MapTheme、Source 等内容结构落到 Markdown 或 Astro Content Collections。

**交付物**：

- 内容 schema。
- 示例 MapTheme：聚窟洲、火罗国、龙隐洞天。
- 少量示例 Dish 和 Meme，未考证内容标注“待考证”。
- 来源状态展示规则。

**验收标准**：

- 页面模板从内容数据读取，不硬编码菜品列表。
- 缺少来源的梗不会显示为已核验。

## 阶段 4：首页、菜单页和详情页 MVP

**目标**：完成第一条核心浏览路径。

**交付物**：

- 首页。
- 菜单页。
- 菜品详情页。
- 地图主题入口。
- 基础响应式样式。

**验收标准**：

- 用户能完成“首页 -> 菜单 -> 菜品详情”的路径。
- 移动端和桌面端均可读。
- 页面视觉主色偏红，但不过度依赖单一红色。

## 阶段 5：投稿与维护流程

**目标**：让社区能通过 GitHub 参与内容维护。

**交付物**：

- 投稿页。
- GitHub Issue 模板。
- Pull Request 检查清单。
- 内容来源和授权审核清单。

**验收标准**：

- 投稿者能按模板提交新菜品、来源补充或画廊作品。
- 维护者能判断内容是否可合并。

## 阶段 6：画廊与主题体验增强

**目标**：增强社区作品展示和地图主题浏览体验。

**交付物**：

- 画廊页。
- GalleryItem 内容模型落地。
- 主题页视觉差异化。
- 作者署名和授权展示。

**验收标准**：

- 每个画廊作品都有作者、来源和授权说明。
- 地图主题能帮助用户理解内容分区。

## 阶段 7：自动化、发布与长期维护

**目标**：降低长期维护成本。

**交付物**：

- GitHub Actions 构建和部署。
- 内容字段完整性检查。
- 更新日志或“本周上新”机制。
- 贡献者说明补充。

**验收标准**：

- PR 能自动运行构建检查。
- 合并到发布分支后可自动部署到 GitHub Pages。
- 新维护者能根据文档完成一次内容更新。
