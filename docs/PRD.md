# NARAKA Restaurant 产品需求文档

## 项目简介

NARAKA Restaurant 是一个《永劫无间 / NARAKA: BLADEPOINT》玩家同好创作站。它用“虚拟游戏主题餐厅”的形式包装玩家梗：用户像浏览餐厅官网一样查看菜品、套餐、地图主题、梗来源和社区作品。

本项目不是官方网站，不销售真实餐品，不提供官方资料库。第一目标是让玩家快速理解和分享社区梗，同时让维护者能通过 GitHub 持续更新内容。

## 目标用户

- 《永劫无间》玩家：想轻松浏览社区梗、菜单化二创内容和梗来源。
- 社区内容创作者：想投稿菜品设定、梗来源、图片作品或菜单文案。
- GitHub 维护者：想用清晰的数据结构审核、补充、修正内容。
- 新玩家或路人：想通过轻量解释理解玩家交流中的梗，但不需要完整游戏攻略。

## 核心用户路径

1. 访客进入首页，看到“非官方同好创作站”声明和虚拟餐厅定位。
2. 访客进入菜单页，按地图主题或标签浏览菜品。
3. 访客打开菜品详情，阅读菜品文案、相关梗、来源记录和“待考证”状态。
4. 访客进入地图主题页，在聚窟洲、火罗国、龙隐洞天等主题中浏览对应菜品和作品。
5. 创作者进入画廊页，查看社区作品展示规则和署名方式。
6. 投稿者进入投稿页，根据模板提交新梗、新菜品、来源补充或画廊作品。
7. 维护者通过 GitHub Issue 或 Pull Request 审核来源、授权和文案后合并。

## 页面列表

- 首页：项目定位、今日推荐菜品、地图主题入口、投稿入口、非官方声明。
- 菜单页：菜品列表、主题筛选、标签筛选、来源状态提示。
- 菜品详情页：菜品名称、虚拟价格或辣度等菜单信息、梗说明、来源列表、相关角色、相关作品。
- 地图主题页：聚窟洲、火罗国、龙隐洞天等主题介绍，以及主题下的菜品和画廊作品。
- 梗来源页：按梗或来源状态整理考证记录，区分“已核验”和“待考证”。
- 画廊页：社区作品列表、作者署名、授权说明、关联菜品或梗。
- 投稿页：投稿规则、GitHub Issue/PR 指引、内容和授权检查清单。
- 关于页：非官方声明、版权说明、维护者说明、撤稿和联系渠道。

## 第一版 MVP 范围

- 静态网站，可部署到 GitHub Pages。
- 首页、菜单页、菜品详情页、地图主题页、投稿页、关于页。
- 使用 Markdown 或内容集合管理菜品、梗、来源和地图主题。
- 至少建立 3 个地图主题：聚窟洲、火罗国、龙隐洞天。
- 只放少量示例内容。具体梗如果没有可靠来源，必须标注“待考证”。
- 示例菜品可以包含“豆浆烩面（待考证）”，但不得声称其来源已确认。
- 每个菜品至少展示：名称、主题、标签、简介、梗说明、来源状态、来源列表。
- 每个页面都应能看到或链接到非官方声明。
- 提供 GitHub 投稿说明和内容审核规则。
- 不接入后端、数据库、用户登录或支付。

## 第二版功能

- 菜品和梗的站内搜索。
- 更细的筛选：地图主题、角色、来源状态、标签、更新时间。
- GitHub Issue 模板：新增菜品、补充来源、提交画廊作品、请求删除。
- 画廊页正式上线，支持作品分类、作者页或作者筛选。
- 更新日志或“本周上新”栏目。
- 自动检查内容 frontmatter 的字段完整性。
- 更完整的 GitHub Actions 部署流程。
- 可选的多语言页面，但中文仍为主维护语言。

## 不做什么

- 不做官方网站，不模拟官方公告或官方资料站。
- 不销售真实食品、周边或付费内容。
- 不做游戏攻略数据库、英雄强度榜、战绩查询或对局工具。
- 不上传未授权游戏素材、未授权二创作品或从客户端提取的资源。
- 不做用户登录、评论系统、点赞系统或私信系统。
- 不把未核验的社区传闻写成事实。
- 不收集现实玩家隐私信息。

## 风险和版权注意事项

- 商标和版权风险：项目必须持续标注非官方身份，避免让访客误以为与官方有关。
- 素材授权风险：图片、字体、图标、视频截图和社区作品都需要可核验授权或可用许可。
- 梗误传风险：社区梗容易变形，来源不足时只能标注“待考证”。
- 社区冲突风险：梗内容可能涉及玩家群体争议，文案必须避免攻击性和定向嘲讽。
- 维护成本风险：内容会持续更新，应使用结构化 Markdown，避免把内容散落在模板中。
- GitHub 参与门槛：投稿规则需要足够清晰，让不熟悉 GitHub 的玩家也能按模板提交。

## 验收标准

- 新维护者阅读 `AGENTS.md`、`docs/domain-model.md` 和本文档后，能理解项目边界。
- 第一版实现后，访客能完成“首页 -> 菜单 -> 菜品详情 -> 投稿说明”的完整路径。
- 每个具体梗都能看到来源状态，未考证内容不会被写成已确认事实。
- 网站可以由 GitHub Pages 托管，并能通过构建命令验证。
